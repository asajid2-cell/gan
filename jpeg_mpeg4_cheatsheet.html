Compression = Remove Spatial + Temporal Redundancy

JPEG Baseline Pipeline

  1. Convert color: RGB → YCbCr. Separate luminance from chrominance.
  2. Optionally subsample chroma: eye is more sensitive to Y than Cb/Cr; 2x downsample in both chroma dimensions gives about 50% chroma-data savings.
  3. Split into 8×8 blocks: good compression/complexity tradeoff.
  4. Level shift: subtract 128 from each sample so values are centered around 0 before DCT.
  5. 2-D FDCT: transform pixels into spatial frequencies.
  6. Quantize: divide by quantization table, round to integers. This is the main lossy step.
  7. Zig-zag scan: reorder low-to-high frequencies so zeros cluster at the tail.
  8. Code DC separately: DC coefficient often uses differential coding from the previous block's DC.
  9. Code AC efficiently: run lengths + EOB + Huffman VLC.
Memory Hook
JPEG removes spatial redundancy. Entropy coding is lossless; quantization is what throws information away.

Why DCT + YCbCr Work

  • DCT concentrates most natural-image energy near the low-frequency corner, especially the DC term.
  • Low frequencies capture smooth shading; high frequencies capture edges, sharp transitions, and noise.
  • Humans notice luminance errors more than chrominance errors, so chroma can be subsampled and quantized more aggressively.
  • After quantization, many high-frequency coefficients become 0, which is exactly what zig-zag + VLC exploit.

Cb ≈ -0.1687R - 0.3313G + 0.5000B + 128
Cr ≈ 0.5000R - 0.4187G - 0.0813B + 128

Zig-Zag, EOB, Decode Path

  • Zig-zag order: moves from DC outward so significant terms appear early and zeros late.
  • EOB: stop symbol for trailing zeros; avoids writing repeated zero coefficients.
  • AC coding: run-lengths of zeros plus coefficient sizes feed Huffman VLC tables.
  • Decode order: Huffman decode → inverse zig-zag → dequantize → IDCT → add 128 → convert back to RGB.
  • Result: entropy-decoded coefficients are exact, but post-quantization image samples are only approximate.
Example tail after zig-zag: [... 2, 0, 0, 0, -1, -1, EOB]

JPEG vs MPEG-4

Redundancy removed Spatial Spatial + temporal

Prediction DC DPCM across blocks Motion vectors across frames/VOPs
Lossy step Quantization Quantization (also residual coding choices)
Entropy stage Huffman VLC/Huffman after scan
JPEG is basically the texture coder inside MPEG-style codecs. MPEG adds motion prediction, reference frames, VOP types, and object tools.

MPEG-4 Overview

  • Goal is not only compression: also error resiliency, authentication, encryption, and scalability in bitrate/resolution/quality.
  • Supports both traditional rectangular frames and object-based / region-based coding.
  • Video coding is based on motion-compensated hybrid DCT coding similar to MPEG-1/2.
  • Encoder is not standardized; the standard fixes the bitstream syntax and decoder behavior.
  • Profiles = tool subsets; levels = complexity bounds such as bitrate, memory, and compute.

Object Hierarchy + Picture Types

VS → VO → VOL → GOV → VOP
  • Video Object Sequence (VS): ordered collection of video objects.
  • Video Object (VO): an object, for example a video entity.
  • Video Object Layer (VOL): one layer per resolution/bitrate variant.
  • Group of VOPs (GOV): analogous to a GOP; supports random access.
  • Video Object Plane (VOP): analogous to a frame, but can contain both texture (YUV) and shape (alpha).
Type Reference rule Compression intuition
I-VOP No MC; intra only Like JPEG; larger size, random-access anchor
P-VOP Predict from previous I/P Send MVs + residual
B-VOP Predict from previous/future I/P Best compression, weakest random access

Coding order is typically not display order. Example pattern from the deck: I0 B1 B2 P3 B4 B5 P6 ...

Texture Coding Inside MPEG

  • Macroblock size is 16×16; texture is split into 8×8 blocks for transform coding.
  • For intra MBs, picture data itself is coded; for inter MBs, the prediction error is coded.
  • Pipeline is effectively JPEG-style: YCrCb conversion, chroma subsampling, DCT, quantization, scan, VLC.
  • In MPEG-4, intra and inter macroblocks can use different quantization matrices because they code different statistics.

Motion Compensation Basics

  • Temporal redundancy: consecutive frames often differ only by motion.
  • Block matching: find best match for a macroblock in reference frame(s), send motion vector (MV) + prediction error.
  • Inter mode: MB depends on other frames. Intra mode: MB decoded without references.
  • Full-pel / half-pel / quarter-pel: finer MV resolution usually predicts better, but costs more interpolation.
Half-pel interpolation: b = (A + B + 1) / 2, d = (A + B + C + D + 2) / 4
P-VOP encoding: split frame into MBs → motion compensate each MB → subtract prediction → DCT-code residual blocks.

MPEG-4 Motion Tools

  • 1MV mode: one MV per 16×16 MB.
  • 4MV mode: split MB into four 8×8 blocks; one MV per block.
  • Quarter-pel MC: 16x finer MV grid than full-pel.
  • MPEG-4 computes half-pel using an 8-tap FIR filter, then quarter-pel from bilinear interpolation.
  • Boundary mirroring: cuts object-edge memory bandwidth.
  • Global motion compensation (GMC): one set of motion parameters can describe pan/zoom/rotation for the whole VOP.
FIR taps for improved half-pel: [-8, 24, -48, 160, 160, -48, 24, -8] / 256
GMC uses 4 corner MVs in the VOP header; MB motion is derived by interpolation ("warping").

B-VOP Modes + Direct Mode

  • MPEG-1/2 B-prediction includes forward, backward, and interpolative modes; MPEG-4 adds direct mode.
  • Direct mode derives the two B-VOP MVs from temporal position plus a coded delta vector instead of sending both explicitly.
  • Skipped B-VOP MBs behave like direct mode with zero delta; if the backward reference is also skipped, implicit skipped mode falls back to forward mode with zero MV.
TRB = t(current) - t(forward ref), TRD = t(backward ref) - t(forward ref)
MVf = (TRB / TRD) MV + MVd
MVb = ((TRB - TRD) / TRD) MV + MVd

MPEG-4 Quantization + Scan Extras

  • quantizer scale controls loss level. For 8-bit textures, range is 1..31; a different value may be used per VOP.
  • Two quantizers: MPEG-style weighting-matrix quantization and H.263-style quantization without weighting matrices.
  • Intra DC coefficient F[0][0] gets a special fixed-step treatment using dc_scaler.
  • AC/DC prediction: MPEG-4 predicts selected AC and DC coefficients for intra blocks from neighbors.
  • Alternative scans: horizontal and vertical scans can beat zig-zag for directional energy.
